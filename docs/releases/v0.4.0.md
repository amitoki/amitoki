# amitoki 0.4.0

`amitoki web`で、PCAPの解析結果と本体の稼働状況をブラウザから確認できるようになりました。React・TypeScript・Tailwind CSSの画面を実行ファイルに同梱しています。

- PCAPを実際のStageで再生し、パケットの加工・破棄、Stageごとの入出力、変更されたフィールド、annotations、Hexを表示します。解析に失敗した場合は前の結果を保持します。
- パイプライン図は設定の接続関係から生成します。起動時の再生構成と、本体が適用済みの稼働構成を切り替えられます。
- 稼働状況では本体の世代・共通カウンタと、Relayごとのキュー・破棄・障害を確認できます。
- Webは転送本体とは別プロセスで動作し、ループバック限定の一時トークン認証、Host/Origin検証を行います。PCAP解析も専用の子プロセスで実行します。
- `debug replay --inspect`で、同じStage入出力の詳細をCLIから取得できます。
- 開発時は`uv run scripts/dev.py`でビルド・API・Viteをまとめて起動できます。HMR、設定・PCAP・ポートの指定、終了時の子プロセス停止に対応しました。

## 起動する

```bash
amitoki web --config ./amitoki.toml
```

表示されたURLをブラウザで開いてください。配布バイナリの利用にNode.js・uv・外部Webサーバは不要です。PCAPの再生には`pipeline`または`pipeline_file`を含む設定と、使用するStageが必要です。

初版はclassic Ethernet PCAPに対応し、入力16MiB・先頭1,000件・解析120秒・同時1件を上限とします。PCAPNG、ライブキャプチャ、Webからの設定編集・reloadは未対応です。解析と監視の範囲は[Web UIの使い方](https://github.com/amitoki/amitoki/blob/v0.4.0/docs/web-ui.md)を参照してください。

## v0.3.0から更新する

本体を更新して再起動してください。既存の転送設定とSDK 0.4.0、中継IPC v1を維持しています。PostgreSQLプラグインv0.2.0・P2Pプラグインv0.1.1は引き続き利用でき、この本体更新に伴うプラグインの更新やDBスキーマ変更はありません。

ソースからビルドする場合はNode.js 24以降を準備し、Cargoの前に`bash scripts/build-web.sh`を実行してください。uvによる開発環境の起動方法も[開発手順](https://github.com/amitoki/amitoki/blob/v0.4.0/docs/web-ui.md#uvでまとめて起動する)に記載しています。

Linux x86_64・ARM64向けの実行ファイルアーカイブとdeb、SHA256SUMSを配布します。両CPUのテスト・配布物検証、Webのブラウザ検証、公開後の匿名ダウンロード検証をCIで実行します。
