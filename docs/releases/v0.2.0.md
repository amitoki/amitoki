# amitoki 0.2.0

RustでPipelineと共有パケット形式を定義し、自作のStageを組み合わせられるようになりました。稼働中のStage・接続変更は、本体とRelayを止めずにreloadで反映できます。

- `amitoki-pipeline`のbuilderで順序・分岐・破棄を宣言し、生成した接続図を`pipeline_file`から読み込めます。`plugin stage`を追加し、従来の`plugin block`も引き続き使えます。
- `amitoki-packet`のcodecと生成器をStageから共用できます。解析→フィルタ→ログの3段を構成するtelemetryの参考実装を追加しました。
- `plugin stage test --packet ... --count 1000`で生成パケットを検証できます。`bench`は件数・時間・投入レート・バッチサイズを指定でき、生成時間とStage/IPCの処理時間を分けて表示します。生成パケットの`watch`にも対応しました。
- `amitoki reload --config ...`とSIGHUPは、新Stageの検証・初期化が成功した場合だけ切り替えます。旧パケットは旧Stageで配送・ACKまで処理し、初期化失敗や期限超過時は旧構成を継続します。
- 稼働中Stageの配布物・設定を更新できるようになりました。本体の再ビルドは不要です。NIC・Relay接続・キュー・重複抑制履歴はreloadで維持します。
- watchの終了確認を改善し、子孫プロセスの終了通知を待って検証するようにしました。

Stage内部のカウンタ・解析状態はreload時に初期化します。NIC・Relay・本体設定を変更する場合は再起動が必要です。実通信へのパケット改変・生成挿入、Stage状態の移行は未対応です。

v0.1.0からは本体を更新して再起動してください。その後、Stageと経路の変更にreloadを使えます。既存のTOML設定・block CLIとPostgreSQL v0.1.2／P2P v0.1.1は引き続き利用できます。SDKは0.3.0で、既存の中継IPC v1を維持しています。

Linux x86_64・ARM64向けの実行ファイルアーカイブとdeb、SHA256SUMSを配布します。Stage・Relayのプラグインは別途追加してください。
