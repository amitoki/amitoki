# amitoki 0.3.0

中継先ごとに送信とACKの処理を分離しました。ひとつの経路が停止してキューが満杯になっても、その経路だけ新しいパケットを破棄し、正常な経路を継続します。Stageによるパケット加工にも対応しました。

- Relayごとの有界キューとワーカーを追加し、経路別の破棄数・待機数・停止時の未配送件数を記録します。再試行で解析や成功済み分岐を繰り返しません。
- SDK 0.4.0のStageは加工後のバイト列を返せます。本体がパケット構造・フィルタを再検証し、配送IDと元のACKを管理します。温度変更・ペイロード消去を行う[telemetry-rewrite](https://github.com/amitoki/amitoki/tree/v0.3.0/plugins/telemetry-rewrite)を参考実装として追加しました。
- `engine.capture_buffer_bytes`で受信バッファを指定できます。既定は4MiBで、OSに制限された場合は警告します。
- VMラボに障害・耐久試験を追加しました。3台・5分の試験ではDB停止中もP2Pを継続し、TCP/UDPの内容と取りこぼしを確認しました。
- PostgreSQLプラグインのsubmodule参照を[v0.2.0](https://github.com/amitoki/amitoki-plugin-postgres/releases/tag/v0.2.0)へ更新しました。送信・受信・履歴SQLを改善し、ACK済みデータの任意の保持期限を追加しています。
- 空のログ、旧DB資材、IDE設定をリポジトリから整理しました。

## v0.2.0から更新する

本体を更新して再起動してください。既存の設定と加工しないStage、中継IPC v1を維持しています。パケット加工Stageは本体v0.3.0以降を使ってください。プラグインは本体の配布物に同梱せず、別途追加・更新します。PostgreSQL v0.1.2とP2P v0.1.1も引き続き利用できます。

PostgreSQLプラグインをv0.2.0へ更新する場合は、プラグインを使う本体を止め、更新版の`--schema`から取り出したSQLを既存DBへ再適用してから起動してください。既存データ・未ACKは維持します。自動削除は既定で無効です。具体的なコマンドは[プラグインの更新手順](https://github.com/amitoki/amitoki-plugin-postgres/releases/tag/v0.2.0)を参照してください。

障害の独立性はRelay単位です。共通NICの障害やStageの停止指定は全体へ影響します。DB再起動後のプラグイン自動復旧、OSサンドボックス、NAT自動通過は追加していません。

Linux x86_64・ARM64向けの実行ファイルアーカイブとdeb、SHA256SUMSを配布します。両CPUでのテスト・パッケージ検証と、公開後の匿名ダウンロード検証をCIで実行します。
