# 外部プラグインとP2Pの実装・検証（2026-09-26）

本体0.3は、中継方式を独立した実行ファイルとして追加する。PostgreSQLとP2Pはaida0710所有のprivateリポジトリへ分離し、本体からsubmoduleでコミットを固定する。本体のmainは変更せず、feat/relay-pluginsで開発した。

## 実装

- CLI: add/list/describe/configure/validate/update/remove。GitHubのprivate Releaseとローカル配布物に対応する。
- 設定: プラグイン自身のJSON Schemaで検証する。CLI保存値をTOMLのrelay.optionsで上書きできる。シークレットは環境変数を参照する。
- 配布: OS・CPU、通信仕様、名前、SHA256を検証する。使用中は設定保存・更新・削除を拒否し、更新はディレクトリの原子的交換で行う。
- IPC: 長さ付きMessagePack、バッチ128件、16MiB上限。呼び出しキャンセルで要求と応答がずれない。子プロセス異常終了時は中継全体の再起動を要求する。
- P2P: 相互認証したQUIC。相手の証明書とnode_idを対応付け、channel違いを拒否する。受信上限と送信側の再試行、ACKと重複除去を持つ。
- 接続情報交換: P2PリポジトリにNext.jsアプリを同梱。Redisで登録を共有し、IP・ポート・証明書fingerprintだけを扱う。

## 実行した試験

RustとNodeの試験は合計44件。通常のcargo testでスキップするDB・隔離ネットワーク・接続情報交換の試験も専用スクリプトで実行した。

| 対象 | 件数 | 確認した振る舞い |
| --- | ---: | --- |
| 本体・メモリ・SDK | 29 | パケット解析、フィルタ、再試行、停止、IPC境界、キャンセル、異常終了、追加削除と破損更新の拒否 |
| Linux隔離ネットワーク | 1 | 3ノードのveth転送と注入フレームの再取り込み防止 |
| PostgreSQL | 3 | 3ノードの再送・ACK・再起動、遅延コミット、登録と送信の競合 |
| P2P | 7 | 3ノード、順序、重複除去、満杯からの復帰、証明書・channel拒否、多重起動、交換サーバ停止後の通信 |

fmtとClippyは本体・両プラグインで確認し、Next.jsのproduction buildも成功した。GitHub Actionsでも本体と各プラグインを独立して検証する。PostgreSQLのCIで初期化用一時サーバをreadinessと誤認する競合が出たため、0.1.1の試験スクリプトはTCPの本稼働待受を確認する。

## 3台の実VM

Ubuntu 24.04の3台のVMでPostgreSQL・P2Pの両方式を試した。a→b、b→c、c→aで1472バイトのICMPを各3回、TCPを各2MiB、UDPを各64件送り、TCP/UDPの内容を照合した。c停止中に送ったUDP64件も、再起動後に全件の内容が一致した。

P2Pの試験ではPostgreSQLを停止した。CLIで使用中のプラグインの削除・更新を拒否し、停止中のプラグインは追加削除できることも確認した。3台ともCargoは存在せず、追加削除の前後で本体のSHA256は一致した。

試験結果はartifacts/vm/2026-09-26/184952/（PostgreSQL）、185031/と185512/（P2P）に保存した。別途、private GitHub Releaseから追加、バージョン固定、設定、検証、更新、削除を実行し、本体のSHA256が変わらないことを確認した。

## 確認した範囲

配布物はLinux x86_64向けで、Ubuntu 24.04のVMで動作を確認した。P2Pは到達可能なUDPアドレスを前提にする。NATの自動通過、STUN/TURN、ブラウザWebRTC、Vercel本番デプロイは含めない。

P2Pの受信キューと重複情報はメモリ上にあり、受信側のクラッシュでは未注入フレームを失い得る。送信側の未送信メモリも永続化しない。ACK後の重複除去は直近65536件まで。PostgreSQLの未ACKデータはDBへ残るが、NIC注入との間のクラッシュでは重複し得る。最大帯域や長時間負荷の保証ではなく、機能と障害時の振る舞いを検証した。
